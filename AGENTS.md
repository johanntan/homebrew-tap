# AGENTS.md

This repository is Johann's personal Homebrew tap. Keep changes small,
reviewable, and compatible with the current stable Homebrew release.

## Repository layout

- Put casks in `Casks/<token>.rb`.
- Put formulae in `Formula/<name>.rb`.
- Keep user-facing installation and security notes in `README.md`.
- Keep scheduled cask updates in `.github/workflows/update-casks.yml`.
- Preserve the workflows generated by `brew tap-new` unless a task explicitly
  requires changing them.

## Cask maintenance

- Use the upstream developer's release as the source of truth.
- Inspect each release artifact before packaging it. Confirm its checksum,
  bundle name, CPU architecture, minimum macOS version, bundle identifier, and
  signing/notarization status.
- Pin every versioned download with a SHA-256 checksum.
- Add a `verified:` value when the download host differs from the homepage
  host or when the URL redirects through GitHub release infrastructure.
- Add a working `livecheck` block. If the asset name contains build metadata,
  retain it as an additional comma-separated version component.
- Add new automatically maintained casks to the `casks` array in
  `.github/workflows/update-casks.yml`.
- Do not use `version :latest` when upstream publishes immutable versioned
  releases.

## Unsigned applications

Some casks in this tap are intentionally unavailable from the official cask
repository because they are unsigned, ad-hoc signed, or not notarized.

- State the exact signing status in the cask caveats and `README.md`.
- Do not add a Gatekeeper bypass by default. Any bypass must be explicitly
  requested by the user, scoped to one cask, and disclosed in both the cask
  caveats and `README.md`.
- Astris is an explicit exception: its `postflight` removes only the
  `com.apple.quarantine` attribute from the installed `Astris.app`. Preserve
  this behavior unless the user asks to remove it.
- Homebrew 6 no longer supports `--no-quarantine`. Tell users to approve a
  trusted app without an explicit bypass through **System Settings → Privacy &
  Security → Open Anyway**.
- A Gatekeeper failure is expected for an intentionally unsigned cask, but all
  checksum, syntax, style, metadata, and livecheck validation must still pass.

## Validation

Run the relevant checks before committing:

```sh
brew style <tap-qualified-name>
brew livecheck --cask <tap-qualified-name>
brew audit --cask --new --online --except=signing <tap-qualified-name>
brew fetch --cask <tap-qualified-name>
```

Homebrew requires casks to live in an installed tap for audit and livecheck.
For a new local repository, commit the candidate changes and temporarily tap
the local checkout:

```sh
brew tap johanntan/tap "file://$PWD"
```

Also run:

```sh
git diff --check
actionlint
```

If `actionlint` is unavailable, at minimum parse every workflow as YAML and
rely on the repository's GitHub Actions checks after pushing.

For an intentionally unsigned cask, do not claim that a full Gatekeeper audit
passed. Report that the signing failure was expected and that the remaining
audit methods passed with `--except=signing`.

## Automatic updates

The scheduled updater runs every six hours on GitHub Actions. It uses each
cask's `livecheck` result and `brew bump-cask-pr --write-only`, validates the
updated cask, commits only `Casks/`, and pushes to `main`.

- Keep action references pinned to immutable commit SHAs.
- Ensure the updater is idempotent when no release is available.
- Test multi-component livecheck versions because `brew bump-cask-pr` must
  update both the `version` and `sha256`.
- Do not add repository secrets or copy a personal GitHub token into Actions
  without explicit user approval.

## Git and GitHub

- Preserve unrelated user changes and stage only files in scope.
- Use terse, descriptive commit messages.
- Do not force-push or rewrite published history unless explicitly requested.
- For authenticated GitHub CLI operations, use:

```sh
op plugin run gh -- <arguments>
```

- Publishing, repository settings changes, releases, and pull requests require
  an explicit user request.
